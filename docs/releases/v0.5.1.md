0.5.1：预编译包不再需要系统库

## 这个版本解决什么

0.5.0 的 tarball 只能装在"恰好有匹配 soname"的机器上：`bin/sandbox` 动态依赖
`libprotobuf.so.32` 与 `libseccomp.so.2`，在别的发行版上要么缺库，要么 soname 对不上。

本版本让发布包真正可移植：

- 新增 CMake 选项 `-DSANDBOX_STATIC_DEPS=ON`，把 libseccomp 与 protobuf 静态链接进去；
- 结果二进制只依赖 `libc` / `libstdc++` / `libgcc` / `libm`（任何 Linux 都有）；
- 发布 workflow 使用该选项构建，所以 Release 附件解包即可运行，不需要 `apt install` 任何东西；
- `tools/pack.sh` 会在打包时打印实际依赖，`tools/install.sh` / `tools/pack.sh` 支持
  `SBX_BUILD_DIR` 指向非默认构建目录。

## 用起来有什么不同

```bash
curl -LO https://github.com/hgdcoco123/linux-sandbox/releases/download/v0.5.1/linux-sandbox-0.5.1-linux-x86_64.tar.gz
tar -xzf linux-sandbox-0.5.1-linux-x86_64.tar.gz -C /opt
/opt/linux-sandbox-0.5.1-linux-x86_64/bin/sandbox doctor
```

包体从 1.4 MB 变为 2.3 MB（静态链接的代价），换来的是不管对方装没装 protobuf 都能跑。

## 已验证

| 项 | 证据 |
|---|---|
| 静态构建 | `ldd` 只剩 libc/libstdc++/libgcc/libm |
| 包可用 | 解包后 `sandbox --version`、`run --process --summary` 正常，`sandbox_ai` 可导入 |
| 默认构建未受影响 | 不加选项时仍走动态链接，`ctest` 34/34 |

## 未变

功能、报告格式（`schema_version` 2）、字段语义与 0.5.0 完全一致；这是一次打包与发布改动。
