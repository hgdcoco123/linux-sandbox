0.5.2：解包就能装，不需要 git

## 这个版本解决什么

上一版把安装拆成了"先 clone 仓库，再跑安装脚本"。在真机上这不成立：一台机器没有 `git`，
另一台到 `github.com` 的 TLS 握手直接被切断。而预编译包本来就是自包含的，**它不需要 git**。

本版本让发布包自己带安装器：

```bash
sha256sum -c linux-sandbox-0.5.2-linux-x86_64.tar.gz.sha256
mkdir -p ~/.local && tar -xzf linux-sandbox-0.5.2-linux-x86_64.tar.gz -C ~/.local
~/.local/linux-sandbox-0.5.2-linux-x86_64/install.sh
```

`install.sh` 做三件事并给出判定：把 `sandbox` / `sandbox-launcher` / `sandbox-ai` 链接到
`~/.local/bin`；跑一次冒烟测试（**必须返回 10**，即 `exit 3` 的 `target_failed` 判定）；报告隔离是否可用。
需要的东西只有 `tar`、`sha256sum`，有 `python3` 则分析层也可用。**没有 git、没有网络、没有 root。**

## doctor 会告诉你下一步

隔离不可用时，`doctor` 不再只报一个 stage：

```console
$ sandbox doctor
isolation unavailable: kernel.apparmor_restrict_unprivileged_userns=1 blocks unprivileged user
namespaces. Temporarily: sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0 ...
{ ...完整 JSON，含 isolation_probe.remedy... }
```

## 已验证

| 项 | 证据 |
|---|---|
| 发布包自安装 | 解包到任意目录 → `sh install.sh` → 链接成功、冒烟测试 10、正确报告 `stage: make_mounts_private` |
| doctor 建议 | 真机 `sysctl=1` 环境下 `remedy` 与 stderr 一行同时出现 |
| 回归 | CTest 34/34、分析层 108 项、无断链 |
| 静态包 | `ldd` 只剩 libc/libstdc++/libgcc/libm |

## 还是要知道的限制

- glibc 下限仍是 2.38（构建于 Ubuntu 24.04），更老的系统需要从源码构建；
- `install.sh` 只做链接与自检，不改任何宿主策略；放行 AppArmor 需要你显式执行（见 `INSTALL.md` 3.0）。
