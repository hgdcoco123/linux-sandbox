0.5.3：装它只需要 tar

## 普通用户怎么装

**一条命令**（能访问 github 的机器）：

```bash
git clone --depth 1 https://github.com/hgdcoco123/linux-sandbox.git
sh linux-sandbox/tools/quick-install.sh
```

**或者完全不联网地装**（把两个文件拷到目标机，不需要 git、不需要 root）：

```bash
sha256sum -c linux-sandbox-0.5.3-linux-x86_64.tar.gz.sha256
mkdir -p ~/.local && tar -xzf linux-sandbox-0.5.3-linux-x86_64.tar.gz -C ~/.local
~/.local/linux-sandbox-0.5.3-linux-x86_64/install.sh
export PATH="$HOME/.local/bin:$PATH"
```

装完 `sandbox --version` 应输出 `sandbox 0.5.3`；`sbx` 是同一份二进制的别名。

## 本版本改了什么

- 安装器同时链接 **`sbx`**：Ubuntu 的 `policycoreutils-python-utils`（SELinux）也提供一个叫 `sandbox`
  的命令，同名会让人照着 apt 建议装错包；`sbx` 与 `sandbox` 行为完全相同。
- `docs/THREAT_MODEL.md` 新增 **4.1**：AppArmor 阻塞 → `doctor` 的 `remedy` → 只放行本 launcher 的
  profile，作为"只报 stage 是未完成的诊断"这一原则的真实案例。
- `docs/INSTALL.md` 3.0 记入两条真机验证：0.5.2 安装包在隔离下跑通（`isolated: true`、`artifacts_ok: true`）；
  `apparmor_restrict_unprivileged_userns=1` 时用 AppArmor profile 只放行 launcher 即可隔离
  （`available: true`、`stage: completed`）。

功能、报告格式（`schema_version` 2）与 0.5.2 完全一致；这是一次安装体验与文档改动。
