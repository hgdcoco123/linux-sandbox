## 2. 最值钱的一类问题：判定与交付语义

### 2.1 一次运行报"成功"，但产物根本没交出来

- **现象**：报告 `verdict=ok`，调用方去取输出目录，发现是空的。
- **定位**：`internal.log` 显示 init 收到 `STOP` 后直接退出，控制通道对端读到的不是 `INIT_DONE` 而是
  `ECONNRESET`——已发出去的那一帧在关闭时丢了。
- **根因**：把"目标进程正常退出"当成了"这次运行成功"。成功其实是两个事实的合取：
  **进程退出码为 0** 且 **产物已完成交付并落盘**。
- **修法**：`PublishResult` 三态（未交付 / 已交付 / 已交付且 durable）；`workspace.export.ok=false`
  时判定失败并写明原因；验收里加一条"导出被拒不能报成功"。
- **一句话**：*我把"成功"从一个字段拆成了两个事实，任何一半不成立都不许报成功。*

### 2.2 会话关闭被误报成 `host_error`

- **现象**：正常 `close()` 偶尔返回宿主侧错误。
- **根因**：与 2.1 同源——关闭路径上同样存在"对端已写、本地已关"的竞态。
- **修法**：先把 stop 确认读完再退出；关闭期间的迟到回执按序号丢弃，通道作废而非报错。
- **一句话**：*同一个根因会在三条路径上各犯一次，修完要顺着调用链把同类路径都走一遍。*

### 2.3 超时之后复用通道，迟到回执被当成协议错误

- **修法**：每个请求带序号，超时后该序号作废；迟到帧直接丢弃。
- **一句话**：*超时不是"请求没发生"，而是"结果未知"，所以必须能让旧结果无害地到达。*

## 3. 协议与安全

| 问题 | 根因 | 修法 | 教训 |
|---|---|---|---|
| 状态目录权限 0755 | 默认 umask 直接建目录 | 改成 0700 | 临时目录里也可能有敏感产物 |
| 模板里 `${run_dir}` 被拼成 `templates-run//abs/path` | 登记阶段就把含占位符的路径当相对路径解析 | 占位符原样保留，只有执行器替换 | 占位符必须在"正确的阶段"才展开 |
| 未知占位符被静默送进沙箱 | 只做了替换，没做白名单 | 登记阶段拒绝 `${run_dir}` 以外的占位符 | 静默接受未知语法＝把错误推迟到最难查的地方 |
| 老数据库打不开 | 新加的唯一索引建在**已有重复行**的表上，`CREATE UNIQUE INDEX` 直接抛错 | 建索引前先去重 | 新约束要假设"历史数据不干净" |
| 进程双写产生重复行 | SQLite WAL 只保证读不阻塞写 | `flock` 排他 + `PRAGMA user_version` 版本检查 | "单用户工具"也要回答"两个进程同时跑会怎样" |

## 4. AI 契约演进：从"引用一段话"到"行地址"

这是整个项目最有故事的一条线。

### 4.1 让模型自由引用 → 它编造引用文本

- **现象**：结论里引用的"原文"在日志里搜不到，或者跨了好几行。
- **修法（M2）**：只允许**一整行**的引文，且必须是子串。
- **结果**：模型开始指到"真实但无关"的行。

### 4.2 干脆不让它写文本 → 只给 `{id, line}`

- **修法（M4）**：证据带可见行号 `L12| ...`，模型只回 `{id, line}`，原文由程序解析
  （`resolved_citations`）。
- **效果**：**伪造通道被结构性关闭**——它只能指，不能写。
- **但**：`qwen3.8-max` 依旧 1/4：34 条引用、10 次工具调用、187–242 秒、13 万 token，**过度生产**。
- **修法**：硬上限（每列表 12 条、6 次调用、4 个工具）+ 截断原因写进报告。
- **一句话**：*prompt 管不住的行为，用协议和预算管。*

### 4.3 同一批 4 条用例：1/4 → 4/4 靠的不是换模型

| 版本 | 改动 | 通过 |
|---|---|---|
| M1 | 自由文本引用 | 1/4 |
| M3 | 单行引文 | 0/4 |
| M4 | 行地址 `{id,line}` | 2/4 |
| M5 | rerank | 3/4（强模型反而 1/4） |
| M6 | 行地址 + 引用纪律提示 | **4/4** |

- **必须说的限定**：4/4 是**样本内**结果（提示句是在这 4 条上调的）；没有 held-out 就不叫泛化。
- **后来补的 held-out**：3 条全新运行 3/3；但这仍是同一台机器、同一 fixture 家族。

### 4.4 `--self-check` 的钱没进报告

- **现象**：开了自检，`usage` 里没有那次调用。
- **根因**：自检发生在 `usage`/`elapsed` 统计**之后**。
- **修法**：自检移到统计之前，指标改名 `self_check` 并标 `judge=model`（模型意见不是裁决）。
- **一句话**：*测量代码也要被测量——"我加了个指标"和"这个指标真的执行了"是两件事。*

### 4.5 缓存让开关失效

- **现象**：先跑普通分析，再跑 `--self-check`，返回的缓存里**没有**自检。
- **根因**：缓存键没有包含 `self_check` / `require_proposal` 这两个会改变输出的开关。
- **修法**：两个布尔进键；测试断言第二次**真的重新调用**且 `cache_hit=false`。

### 4.6 `--require-proposal` 竟然会稳定 400

- **现象**：强制提案时服务商报错，看起来像模型坏了。
- **根因**：`tool_choice` 点名了 `propose_verification`，但没给模板时这个工具**不在工具表里**。
- **修法**：没有模板就提前报 `needs a template registry`；有模板时改成**按名强制**而不是
  `"required"`（后者只保证"调用某个工具"，模型可以读一下证据就回答）。
- **一句话**：*"强制调用"和"强制调用这个"是两回事，而错误信息决定了你要花多久才能发现。*

## 5. 度量与实验方法（最容易被忽略，也最容易被问倒）

### 5.1 我以为在测分析层，其实在测沙箱

- **现象**：价值实验里"给完整 report"和"给分析"都是 0/3。
- **根因**：被测程序 `cwd` 就是 spec 所在目录——**程序自己能读答案**，模型于是用 `cat spec.txt`
  绕过了整个分析层。
- **修法**：spec 放到程序读不到、只有证据能读到的目录（信息不对称）。
- **一句话**：*如果被测对象能作弊，你的指标只是在测它会不会作弊。*

### 5.2 harness 自己的两个 bug 伪装成"被测对象不行"

- **现象**：某个任务怎么都修不好。
- **根因**：① 三个任务的 `spec.txt` 放同一目录 → 一个任务的证据混进别的任务的期望值；
  ② 所有任务共用 `loop` 作用域 → 别的任务的命令以 `history` 身份出现，分析据此编出"spec 要求 41"。
- **修法**：每任务独立目录 + 独立 scope。修完规则 Agent 从 2/3 变 3/3。
- **一句话**：*测量脚本的错误看起来和被测对象的错误一模一样，所以要先怀疑实验装置。*

### 5.3 分析自己也会错，而且错得更危险

- **现象**：spec 写 `expected=ok` + `max_bytes=64`（上界），分析读成"**恰好** 64 字节"，还漏了 `ok`；
  模型忠实地执行了这条错的分析，写出 64 个 `x`。
- **为什么危险**：它**通过了所有校验**——引用的行是真的。
- **处理**：没有"修到好看为止"，而是写进 `docs/VALUE.md` 当已知失败，并明确"解释错比没有更糟"。
- **一句话**：*引用可以被结构保证，语义不能；所以我只承诺"指向真实行"，不承诺"结论正确"。*

### 5.4 一次跳过测试，藏了一个 `NameError`

- **现象**：Windows 上 78 项全绿，Linux 上 4 个 error。
- **根因**：`test_e2e_driver` 在 Windows 被 `skipIf(posix)` 跳过，而它缺一个 import。
- **修法**：补 import；把"跳过 ≠ 通过"写进验收脚本注释。
- **一句话**：*跳过会掩盖错误，所以我坚持在目标平台上跑测试。*

## 6. 工程与协作

| 问题 | 处理 | 教训 |
|---|---|---|
| 开发在 Windows、沙箱只跑 Linux | 起一个 HTTP 桥把文件/命令送到虚拟机，Linux 上跑全部测试 | 目标平台验证不可替代 |
| 两次把 API 余额跑空 | 加 `--limit` 成本闸 + token 估算 + `Retry-After` 上限 | 会花真钱的实验要有硬闸门 |
| rerank 接口 404 | 兼容端点没有 `/rerank`；探到 DashScope 原生路径 | 适配器要可配路径，并按真实服务验证 |
| 重试会重复计费 | 只对无副作用的 chat/embed/rerank 重试；写进文档 | 幂等是重试的前提 |
| 分块 200 字符重叠 → 同一行两个证据 id | 改行边界对齐、不重叠（≤1800，目标 1600） | 地址唯一性比召回率更重要时，要显式取舍 |
| 小文件（20 字节 spec）检索不到 | 检索查询加调用方上下文；被点名的文件直接前置 | 规定"该做什么"的文件不该靠相关性撞运气 |

## 7. 直接可讲的故事（每个 ~1 分钟，STAR 骨架）

### 故事 A：把"成功"拆成两个事实（系统层 / 可靠性）

- **情境**：验收里出现过"报告成功但产物为空"。
- **任务**：修到"任何一半不成立都不许报成功"。
- **行动**：用 `internal.log` 定位到 `ECONNRESET` 丢帧；改 `PublishResult` 三态；导出被拒/跨界
  时 copy-then-exchange 并 fsync；加验收用例。
- **结果**：验收从 33 项涨到 34 项，全部锁定"导出未完成 ≠ 成功"。
- **可讲的点**：我知道"成功"是一个可被错误定义的东西，并且用测试把它钉住了。

### 故事 B：让模型只"指"不"写"（AI 工程 / 契约设计）

- **情境**：模型引用会编造文本，指到真实但无关的行。
- **行动**：行号标签 → `{id,line}` → 程序解析 → 硬上限 → 两阶段检索。
- **结果**：同一批用例 1/4 → 4/4，并明确说明是样本内。
- **可讲的点**：**能用协议解决的，不要用提示词解决**；prompt 管不住的行为用结构和预算管。

### 故事 C：证明解释有用（实验设计）

- **情境**：AI 层能出结论，但没人验证过它是否**帮到**了谁。
- **行动**：造信息不对称的任务族（期望值只在证据里，程序读不到），三种反馈对照
  （无反馈 / 完整报告 / 结构化分析），两个 Agent（规则表 / 真模型），验证器判定。
- **结果**：0/3 → 3/3（规则）/ 2/3（模型）；且"完整报告"也是 0/3，划出界线。
- **可讲的点**：**规则 Agent 也能修好**，说明收益来自"信息"而不是"模型聪明"。

## 8. 被追问怎么办（10 问速答）

| 问 | 答 |
|---|---|
| 为什么不用 Docker？ | Docker 给的是"容器起来了"，不给"这次运行算不算成功、产物交没交"。我的差异化是判定语义与可审计报告，容器可以做我的下层。 |
| 4/4 是不是过拟合？ | 是样本内结果，我在文档里就是这么写的；后来补了 3 条 held-out（3/3），但仍同机器同域，所以只声称"不是这 4 条上的过拟合"。 |
| 怎么保证引用不伪造？ | 模型只回 `{id,line}`，原文由程序解析；越界、短行、未供给的证据直接拒。伪造没有通道。 |
| 那结论错了呢？ | 引用真实 ≠ 结论正确。我在 `VALUE.md` 里记录了一个分析误读规格的实例，这正是我承诺的边界。 |
| 并发怎么办？ | 单写入者：`flock` 排他 + `user_version` 拒绝更新版库；多写不支持，写进 `CONTRACT.md`。 |
| 证据多了怎么办？ | 分块 + BM25/向量 + RRF + rerank；1 万块以内精确扫描，超过就分 scope。没有上 ANN。 |
| 为什么不用微调？ | 我的问题是"证据可核验"和"工具调用可控"，不是语言能力；微调解决不了伪造引用。 |
| 安全边界在哪？ | `THREAT_MODEL.md`：防用户态越界/资源耗尽/产物篡改，不防内核 0day、侧信道、多租户。 |
| 你怎么知道测试没在自欺？ | 三个例子：跳过测试掩盖了 import 错误；harness 两个 bug 伪装成"被测对象不行"；自检的钱没进报告。 |
| 如果重做，你会先做什么？ | 先写"成功"的判定契约和验收，再写执行；先做威胁模型，再写隔离代码。 |

## 10. 最后一句

这个项目里我修的大部分不是"功能没写"，而是**"系统在给出错误印象"**：报成功但没交付、指标没执行却存在、
测量脚本的 bug 伪装成被测对象的问题、分析把上界读成等号。这类问题不会崩，只会慢慢毁掉可信度——
所以我在文档里给每个断言都配了测试或数字，也把没验证的部分写成"未验证"。
